## Phase 4 — v2.0.0 桌面体验

### 产品目标与范围

把可靠执行底座变成适合长时间工作的 macOS 工作台：更容易找上下文、更少表单负担、更清楚的状态与审批、更好的消息阅读、连贯且克制的动画。坚持功能稳定与数据兼容，体验升级不能改变“先审阅、再确认执行”的约束。

本轮必须完成：设计系统（深浅/系统主题）、动效与减少动态、可折叠/可调整布局、底部会话输入、流式 Markdown、阅读锚点、指挥官审阅与执行信息层次、审批上下文、看板拖拽反馈、设置引导、命令面板、键盘/无障碍、性能回归和 macOS 安装发布。

不纳入：代理引擎重写、新云服务/账号同步、协议扩张、原生驱动产品接入、自动执行/整计划重试、可编辑 DAG、Windows/Intel 发布、ZCode 解禁、自动更新。新需求先评估并入明确任务，不塞入视觉重构。

### 建议技术方向

沿用 shadcn/Radix + Tailwind，建议增量采用 Motion、cmdk、react-resizable-panels、Sonner；Streamdown 先做对照样例；保留 dnd-kit、react-virtuoso、xterm 与现有 diff。具体许可、适配风险、动效及预算见 [设计方向](design/desktop-v2.md)。选型必须通过 P4-2 的 React 19/Tauri WebKit 检查后才固定，不在规划阶段大量安装库。

### 任务与依赖

所有任务均需 `just verify`，下表补充各项特有出口。耗时是单项开发粗估；超出 2 天须开工前拆分。每项开工时先在 `acceptance/p4-*.md` 预写数据、命令、平台、预期，再实现；涉及接口/迁移/行为先更新 architecture，对重大取舍写 ADR。下表的“新增”都是规划，不能据此断言已有实现。

### 阶段检视点

| 检视点 | 完成条件 | 产出 |
|---|---|---|
| G1 方向可审阅 | P4-1～2 | 基线、原型、三类动效录像、选型与许可核对；此时可调整视觉方向，避免重做五页 |
| G2 一条高质量会话路径 | P4-3～12 | 新布局/主题/动效/输入/阅读/终端真实可用，底层执行行为不变 |
| G3 五页体验一致 | P4-13～20 | 指挥官、审批、看板、设置和命令入口共用规范 |
| G4 可发布 | P4-21～24 | 性能/无障碍/真实模型/数据升级/安装/远端发布全过 |

检视点不替代每任务闭环；不会自动打 tag 或发布体验包。总量粗估约 39 个开发日，不含等待认证/证书、设计返工和缺陷扩项；不作为交付日期承诺，P4-2 后按结果重估。

## 2.0 统一出口

- 保持 1.0 的确认、审批、取消、会话/worktree 归属与终端资源清理；UI 重构不能引入自动执行/永久放行或隐式重跑。
- 以 [设计方向的预算表](design/desktop-v2.md#7-预算与验收方法)为验收起点；P4-1 固定采样方法，未达标要如实标待验收。纯浏览器演示不能代替 Tauri WebKit。
- 所有新自动检查进入 just verify；新增接口/状态机必须先有有意义契约测试。UI 边界测试覆盖 IME、焦点、草稿、滚动和一次性提交；不堆实现镜像测试。
- 新偏好/索引若用 SQLite，先设计迁移并验证 1.0 数据；真实 endpoint/model/key、SQLite 不上传 GitHub。展示/网络日志脱敏，不采集未授权遥测。
- 真正的 Phase 4 与安装/远端验收归档后才发布 2.0；版本规划不能写成已交付。当前 1.0 的签名/公证限制不因 UI 升级自动消失。
