# v2.0.0 桌面体验分析与设计方向

> 规划日期：2026-10-08。本文是目标与选型建议，不代表已实现设计。P4-1 的测量见 [基线](../acceptance/p4-1.md)，P4-2 独立原型与精确候选见 [决策](desktop-v2-prototype.md)；生产界面尚未改造。任务顺序/状态只看 [roadmap](../roadmap.md)，开发规则只看 [development-process](../development-process.md)。

## 1. 结论与边界

建议将 2.0 定位为「围绕任务工作的 macOS Agent 工作台」：保留 1.0 的可靠执行底座，把找任务、输入目标、审阅、审批、追踪结果这些高频动作连起来，同时统一视觉与动画。

v1.0.0 已完成批准范围；Windows、ZCode 是明确延期，并非已经开发/验收完成。2.0 延续 macOS Apple Silicon 路线；不把新协议、多端同步、插件市场、云服务或 Agent 引擎重写混入体验升级。NativeDriver 产品入口仍是独立后续议题。版本号只在发布准备时升级，不在规划阶段修改。

## 2. 现状与机会

下表的现状来自源码及 v1.0.0 验收；“影响”是待 P4-1 用任务走查/性能记录验证的判断，不冒充用户研究或已测量结论。

| 观察依据 | 现状 | 2.0 改善方向 |
|---|---|---|
| App.tsx / SessionsWorkspace | 全局导航与固定宽度会话栏占用横向空间，缺少统一搜索/命令入口 | 可折叠导航、项目上下文、可调整分栏；保持现有模块可达 |
| RunConsole | 提示词、cwd、模式、规则等表单集中顶部；消息与操作区域割裂 | 底部固定输入区，常用项直达，目录/规则等进入上下文弹层；风险模式仍明确展示 |
| StreamItemView | 消息/思考主要为纯文本，Markdown 没有完整排版 | 流式 Markdown、代码复制、思考/工具分层折叠；保留原文与虚拟列表 |
| CommanderView | 目标表单、历史、任务结果叠在同一纵向页面；确认弹层为手写布局 | 生成/审阅/执行视图清晰分工，任务列表+详情检查器、正确焦点管理 |
| SettingsView / CommanderSettings | 多类设置纵向堆叠，连接保存、密钥来源、真实可用性容易混淆 | 设置分组与分步配置，明确“已保存 / 未验证 / 验证失败 / 验证成功”；不以安装探测替代推理验证 |
| PendingCard | 已有一次性裁决与会话隔离，但 raw_input 主导展示、错误反馈空间有限 | 命令/文件变更预览、所属任务、结果反馈；失败留在原卡，不悄悄移除 |
| index.css / SessionTerminal | 已有颜色 token，但页面控件/层次不完全统一，终端主题固定 | 完整主题/密度/字体规范，深浅主题和系统跟随，终端与代码区协调 |
| package.json | 已有 shadcn/Radix、Tailwind、dnd-kit、react-virtuoso、xterm、Pierre diffs；尚无统一 Motion 层 | 复用底座，少量增量依赖；先测真实 WebKit，不因演示站顺滑就宣称桌面兼容 |

## 3. 视觉与交互方向

**视觉主张**：安静、精确、有空间感的原生桌面工作台，以排版、留白与轻微表面层次建立品质，单一品牌强调色，成功/警告/失败采用语义色。

**内容结构**：导航负责定位；项目/会话列表负责找上下文；中间工作区负责输入和阅读；按需打开的检查器负责详情，底部工具区负责终端。每块仅承载一项主要职责。保留“指挥官、会话、看板、审批、设置”入口，先减少重复层级，再评估导航细节。

**交互主张**：选中与焦点立即响应；抽屉和弹层有短距离连续过渡；任务移动保留空间关系；输入、滚动和审批始终优先于动画。动效集中在 3 个有辨识度的场景：工作区切换、详情展开/收拢、看板落位；不让每一条流式 token 做进场动画。

目标布局：

```text
┌ 导航 ─┬ 项目 / 会话 / 计划 ─┬ 当前工作区 ─────────┬ 详情（按需） ┐
│ 搜索  │ 搜索、分组、状态     │ 消息 / 审阅 / 看板   │ 工具、任务   │
│ 模块  │ 当前上下文          │                    │ 完整 prompt  │
│ 审批数│                    │ 底部输入区           │ 依赖 / 结果  │
│ 设置  │                    ├ 终端（按需）─────────┴─────────────┤
└───────┴────────────────────┴───────────────────────────────────┘
```

这是信息分工，不强制五列同时显示。960×640 时折叠次要面板，1280×800 时优先双栏，宽窗口才显示检查器；主阅读区不被挤成窄条。控件保持真实产品语言，不显示任务阶段编号、测试按钮或设计说明。

## 4. 开源方案研究

2026-10-08 核对官方文档与源仓库。以下“建议”是规划，不是已安装或已完成兼容测试；具体稳定版本、peerDependencies、许可证文件和体积在 P4-2/P4-3 固定，不使用 `latest` 自动升级生产依赖。

| 方案 | 用途与选择 | 来源/许可依据 | 风险与取舍 |
|---|---|---|---|
| shadcn/ui + 当前 Radix/Tailwind | **继续作为唯一基础组件体系**；补 Dialog/AlertDialog、Popover、Select、Tabs、Sidebar 等，统一样式 | [官方组件](https://ui.shadcn.com/docs/components)、[MIT](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md) | 按需引入源码，避免再叠 Ant/MUI/Mantine；现有 Radix 不为追新迁至另一套 primitive |
| Motion for React | **建议引入**统一动效，存在/退出、布局与轻量弹簧；CSS 负责简单 hover/focus | [可访问性](https://motion.dev/docs/react-accessibility)、[LazyMotion](https://motion.dev/docs/react-lazy-motion)、[MIT](https://github.com/motiondivision/motion/blob/main/LICENSE.md) | 使用开源核心，排除 Motion+ 付费内容；大列表不整树 layout；WebKit/React 19 实测后固定配置 |
| cmdk，经 shadcn Command 封装 | **建议按需引入** Cmd-K 命令面板，先搜索模块/已加载会话/任务并跳转 | [Command](https://ui.shadcn.com/docs/components/radix/command)、[源仓库/MIT](https://github.com/dip/cmdk) | 中文输入法组合输入不触发执行；端到端搜索不能假称“已加载列表过滤”是全库全文搜索 |
| react-resizable-panels | **建议引入**工作区/详情/终端分栏与键盘调整 | [shadcn Resizable](https://ui.shadcn.com/docs/components/radix/resizable)、[源仓库/MIT](https://github.com/bvaughn/react-resizable-panels) | 与当前 shadcn 示例 API、具体包版本对齐；隐藏/resize 时 xterm fit 和清理行为不回归 |
| Sonner | **建议按需引入**复制/保存等短反馈 | [官方封装](https://ui.shadcn.com/docs/components/radix/sonner)、[源仓库/MIT](https://github.com/emilkowalski/sonner) | 重要错误/待审批保持内联且可追溯；Toast 不替代确认或裁决，不重复播报 token |
| Streamdown | **候选，先做对照样例**；针对未闭合 Markdown 的流式展示 | [官方仓库](https://github.com/vercel/streamdown)、[Apache-2.0](https://github.com/vercel/streamdown/blob/main/LICENSE) | 在真实增量文本、中文、长代码块、虚拟列表/WebKit 上测量；只启用必要功能，未达预算则采用较小 Markdown 组合或静态完成后渲染，保留纯文本回退 |
| 当前 dnd-kit / react-virtuoso / xterm / Pierre diffs | **保留**拖拽、虚拟化、终端与 diff，先统一交互 | 项目当前 package.json 与实际 import | 不用动画库抢拖拽 transform，不替换 PTY 或重写列表；清理未使用依赖并核对许可证，避免误引付费消息列表包 |
| Animate UI | **仅作视觉/交互参考，默认不引入** | [官方介绍](https://animate-ui.com/docs)、[当前 LICENSE](https://github.com/imskyleen/animate-ui/blob/main/LICENSE.md) | LICENSE 标注 MIT + Commons Clause，而 README 简述 MIT；不能当作无附加条款的 MIT 库。若未来选用，需按具体版本核对授权及分发边界 |

“丝滑”由数据更新节奏、滚动锚点、渲染成本、输入反馈与动画协同实现，安装 Motion 本身不能保证。无需同时引入多套动画引擎，不为展示炫技加入粒子背景、满屏模糊、磁吸光标或持续漂浮。

## 5. 动效规范候选

| 场景 | 初始设计范围 | 行为约束 |
|---|---|---|
| hover / press / focus | 80～140ms，颜色/透明度或很小位移 | 按下立即反馈；不缩放正文，不移动审批点击目标 |
| Popover / Dialog / Sheet | 140～220ms，opacity + 4～12px translate；小组件可轻弹簧 | 关闭后焦点回触发点；取消/确认点击立即处理，不等待退出动画；不重复提交 |
| 侧栏 / 详情切换 | 180～240ms，位置连续、被替换内容淡入 | 不整页飞入，不 remount 执行宿主，不重连/重跑任务 |
| 看板落位 | 160～240ms，拖拽时直接跟手，落位时平滑重排 | 单一 transform 所有者；保存失败回滚可见，键盘路径等价 |
| 流式文本 / 终端 | 文本自然追加；仅状态指示器轻动效 | 不逐字强制延迟，不对历史列表逐项入场，不阻止滚动/选择/复制 |

这是可调的设计起点，不是组件库保证值。动效统一配置；默认跟随 `prefers-reduced-motion`，并提供应用内“系统/减少/完整”偏好。减少模式禁用大位移、弹簧、持续 shimmer，保留清晰状态。切后台暂停纯装饰循环；主题切换不做整屏闪烁。动画结束不能决定持久化、取消、裁决或资源回收。

## 6. 交互重点

- **会话**：底部输入；中文 IME、Shift-Enter、多行粘贴；Agent 与权限常驻可识别、目录可见且锁定语义不变；流中向上阅读不抢滚动，有新消息提示；历史和新生成显示一致。
- **指挥官**：项目/Agent 可选择而非逗号手填；生成、审阅、执行、结果阶段明确；任务详情可看完整 prompt/依赖；SQLite 状态继续权威，导航不会停止运行；执行仍须明确确认，失败后代/取消不被“完成”动画掩盖。
- **审批**：在任务/会话上下文中看命令或变更；待决徽标可导航；同名 tool ID 不串台；减少点击负担不等于批量放行、扩大权限或默认允许。
- **设置/初次使用**：按模型、Agent、外观、规则分组；提供目录选择与连接状态；密钥写本机，重开 App 直接可用；验证动作明确是否产生 API 调用，列表查询不等于推理成功。
- **反馈**：空白、加载、排队、运行、成功、失败、中断、取消均有相应文案；Toast 用于短反馈，错误和待决状态必须留在操作附近。仅在失败不产生重复副作用时提供重试，不新增自动重跑已确认/终态计划。

## 7. 预算与验收方法

以下均为 2.0 目标，当前未完成 2.0 实现的测定。P4-1 已记录 1.0 基线与设备，后续同机器/同数据/同 release 构建比较；若目标不成立先拆分或优化，不把目标改写成已通过。

| 指标 | 验收场景/预算 |
|---|---|
| 输入反馈 | release + 固定 fixture，输入/点击到可见反馈 p95 ≤100ms；排除真实网络耗时，记录至少 30 次操作，IME 组合输入另测 |
| 流畅性 | 60Hz 屏幕，固定 30s 滚动/分栏拖动/消息追加记录，目标 p95 帧间隔 ≤20ms；统计主线程 >50ms 长任务及来源。仅用 rAF 只能近似帧节奏，WebKit 时间线/录像辅助核对 |
| 长会话 | 1000 条混合消息、中文/长代码/100 个工具节点，固定 20 次/秒事件输入；DOM 保持虚拟化、有新消息提示，滚动锚点不跳、事件不丢；大代码高亮按需加载 |
| 资源 | 冷启动 5 次中位数相对 1.0 基线不退化超过 10%；稳定内存同场景不增长超过 20%；20 次切页/终端开关后无进程泄漏或持续内存上升 |
| 包体 | 同构建工具口径，初始加载 gzip JS 相对基线增幅 ≤20%；重 Markdown/diff 功能 lazy load，增量依赖超过预算须先解释/减重，不简单忽略构建警告 |
| 键盘/可访问性 | 五页关键流程无需鼠标可达；Dialog 焦点圈定/返回，Esc 与现有快捷键不冲突；VoiceOver 可读名称与状态；减少动态模式等价可用；正文对比度目标 4.5:1 |
| 兼容 | 960×640、1280×800、1440×900 CSS 像素，深/浅/系统主题，长目录/中文/英文/空白与错误场景；实际 Tauri WebKit 验收，浏览器截图不能代替 |

性能采样工具/脚本在 P4-1 确定；自动回归能力在 P4-3 加入 `just verify`，不提前添加空跑测试。时间数字不可只靠主观“看着流畅”判定。可访问性数值为产品验收目标，不能据此宣称已获得标准认证。

## 8. 实施节奏与发布边界

顺序为：基线/设计与选型 → 验证基础 → 主题/动效/布局 → 会话 → 指挥官与审批 → 看板/设置/搜索 → 性能与无障碍 → 阶段与安装发布。详细拆分见 roadmap。

优先完成一条贯穿流程：打开项目 → 选择 Agent → 输入 → 查看输出 → 审批 → 终端/结果 → 重启恢复。随后把同一套交互应用于其它页面，避免五页独立设计。

每项控制在 0.5～2 个开发日，表内为粗估而非承诺日历；真实认证、设计迭代和缺陷修复会影响周期。若任务超过两天，开工前继续拆分并更新依赖。中途需要体验包时单独认领预发布任务并执行安装验收，不把 dev 自动命名为正式 2.0。

保持 1.0 数据可读：外观/布局/新索引等需要持久化时，先设计 architecture/迁移，再用不含真实凭据的 1.0 fixture 验证升级；不重建用户库、记录脱敏、不回退到环境变量唯一来源。模型/代理协议、权限边界与运行状态机默认不变。

Apple Developer ID 签名/公证仍依赖实际证书与账号；安装发布任务必须如实记录是否具备，不将“有漂亮 UI”当作完成签名。Windows/Intel、ZCode、Native 产品接入、云同步、自动更新、可编辑 DAG、自动重试整套计划是后续候选，均不作为本轮默认前置项。
