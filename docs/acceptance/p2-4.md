# P2-4 Codex ACP 接入验收

## 预写验收步骤

1. `just verify`：前端构建、Rust fmt/clippy/test 全绿；协议契约测试覆盖 Codex 通知/权限选项，以及双会话隔离中涉及的事件路由。
2. `cargo run -p supercode-cli -- detect`：显示 Codex ACP 适配器版本；缺失时设置页给可复制安装/认证引导。
3. `SUPERCODE_DB=/tmp/sc-p24.db cargo run -p supercode-cli -- run --agent codex --cwd /tmp/sc-p24-codex '创建 hello.txt 内容为 P24-CODEX，读取并复述；记住暗号 P24-CONTEXT-928'`：流式文本、Write/Read 工具事件、如有权限请求则完整命令/路径及 y/n 应答可见，以 EndTurn 收尾；文件内容与回复一致。验收仅操作临时目录。
4. `SUPERCODE_DB=/tmp/sc-p24.db cargo run -p supercode-cli -- sessions list`，随后 `resume <UUID> '刚才的暗号与文件内容是什么？'`：使用 Codex 适配器和原 ACP session id，通过 session/load 正确回答暗号与文件内容。
5. 并行：在独立 cwd 中同时启动 Codex 与 Claude Code，提示词分别要求回复 `P24-CODEX-ONLY` / `P24-CLAUDE-ONLY`；两个会话的事件、状态、持久化 agent_id 及续聊互不串台。桌面 `pnpm tauri dev` 双会话复核同一行为。
6. macOS UI：新会话可选 Codex、Node/npx 与认证引导显示；Codex 会话审批在内联卡片应答；重启后历史仍绑定 Codex。原 OpenCode/Claude 会话可继续使用。
