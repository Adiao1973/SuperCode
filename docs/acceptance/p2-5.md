# P2-5 MiMo ACP 接入验收

## 预写验收步骤

1. `just verify`：前端构建、Rust fmt/clippy/test 全绿；MiMo 注册表命令、能力位及选择器/指引的确定性检查通过。
2. 从官方 npm 包临时安装 MiMo CLI，不修改全局安装；`mimo --version`、`supercode detect` 显示 MiMo 版本。未安装时设置页提供可复制安装命令和认证说明。
3. 在独立 `/tmp/sc-p25-*` 工作目录用 CLI `run --agent mimo` 完成真实任务：写 `hello.txt`、读回、流式消息及工具事件可见；如发生 ACP 权限请求，在 CLI 或桌面内联卡片应答，并以 EndTurn 收尾。认证或模型选择由 MiMo 自身管理，不读取用户凭证。
4. 使用数据库记录的本地 UUID 新进程 `resume`：以原 MiMo agent/cwd/ACP session id 加载历史，准确复述文件内容与暗号。
5. macOS 桌面新会话可选择 MiMo；与另一 ACP agent 同时运行时，消息、工具、审批、状态各自归属正确。关闭重启后 MiMo 历史仍绑定 MiMo，并可续聊。
6. 若官方 CLI 在当前环境缺少可用认证或模型服务，记录精确阻塞和已通过的协议/界面范围；不以安装探测代替真实任务通过，也不提前把 P2-5 标为已验收。

## 阶段结果（2026-09-29，尚未通过完整验收）

- 官方 `@mimo-ai/cli` 0.1.15 安装在 `/tmp/sc-p25-mimo`，未改全局 CLI；`mimo --version` 与设置页探测均显示 0.1.15。独立 XDG 配置、数据、缓存与 SuperCode SQLite 均在 `/tmp/sc-p25-*`。
- `just verify` 全绿：前端构建、Rust fmt/clippy、core 65 passed / 1 ignored、ACP 合同测试 4 passed、desktop 2 passed。新增测试覆盖 MiMo 从会话 cwd 启动、旧注册表兼容、嵌套 IPC 字段，以及 ACP 空轮次错误。
- 首次从仓库目录启动 `mimo acp`，会话 cwd 指向 `/tmp`，`session/new` 失败。MiMo 日志明确记录 `directory_not_allowed`；只附加 `--cwd` 无效，0.1.15 的服务根目录仍是进程当前目录。改为从会话 cwd 启动子进程后，同一命令可获得 `ses_...` ACP session id，数据库保存 `agent_id=mimo`、原 cwd 与状态；跨进程 `resume` 使用同一 ACP session id 完成 `session/load`。
- MiMo 自带的匿名 MiMo Auto 通道在临时配置中可初始化，但原生 `mimo run --model mimo/mimo-auto` 返回 `MiMo free API service has ended. Sign in or configure a third-party API.`；ACP 请求则返回 0 token、无消息或工具事件的 EndTurn。为避免误报，驱动现将这种空轮次报错并把会话标为 failed。CLI 退出码为 1，桌面会话显示“出错”和模型/认证提示。
- macOS 临时应用中，新会话可选择 MiMo，折叠指引含官方安装命令及 `mimo providers login`；设置页显示 MiMo 0.1.15。失败会话在应用重启后仍保留 MiMo agent 与原 cwd，历史可打开。
- 为隔离真实模型不可用的问题，在独立 XDG 临时配置中将 MiMo 指向本机 `127.0.0.1:18765` 的一次性 OpenAI 兼容模拟端点（固定响应，无外部模型调用）。真实 MiMo ACP 进程经该端点流式回复 `P25-MOCK-READY`；新进程 `session/load` 重放并续聊均通过。模拟端点发出 write → read 工具调用时，CLI 展示两次 `external_directory` 权限请求，分别选择一次允许；工具状态均为 Completed，`mock.txt` 内容为 `P25-MOCK-FILE`，数据库记录 2 次工具调用与 2 次审批。桌面内联卡片复核同一顺序、完整路径、两次 Allow once、读回内容与最终回复，数据库会话状态为 completed。

截至首次验证尚未通过：由**真实模型**驱动的写入/读回、有效上下文续聊，以及与另一 agent 的真实并行任务。模拟端点只能证明 MiMo ACP 与 SuperCode 的协议、工具和审批链路，不能替代模型行为验收。需在 MiMo CLI 中配置可用供应商后重跑第 3—5 步；不在本记录中把协议建会话或空 EndTurn 视为任务成功。凭证无需提供给 SuperCode 或聊天。后续补充验证见下节。

## 补充验证（2026-09-29，复用本机现有配置）

- 本机 `~/.mimocode/bin/mimo` 为 0.1.15，当前 shell 的 `PATH` 未包含该目录。`mimo providers list` 显示 0 credentials、`providers whoami` 显示未登录，但全局配置已有供应商设置；原生 `mimo run '请只回复 OK'` 成功调用 `xiaomi-token-plan-cn/mimo-v2.5` 并回复 `OK`。因此该配置无需重新输入 key。没有读取、复制或记录密钥值。
- ACP 默认模型一度选中 `google-vertex/gemini-3-pro-image` 并持续请求失败。只在 `/tmp/sc-p25-real-20260929/.mimocode/mimocode.jsonc` 指定 `xiaomi-token-plan-cn/mimo-v2.5` 后重试；未改全局配置。此模型选择差异需在日常使用前明确配置。
- `SUPERCODE_DB=/tmp/sc-p25-real-20260929/supercode.db`、`PATH="$HOME/.mimocode/bin:$PATH"` 下，`supercode detect` 显示 `MiMo 0.1.15 ✓`。`run --agent mimo --cwd /tmp/sc-p25-real-20260929` 的真实模型轮次执行 bash 写入与 read 读回，最终回复 `P25-REAL-MIMO-729`，磁盘 `hello.txt` 内容一致，EndTurn 收尾；会话 id `e10c2d58-03fc-43a6-bbc1-e8b67acc5041`。这次工具调用没有触发 ACP 审批，故真实模型的权限交互仍以先前模拟端点结果为准。
- 新进程 `resume e10c2d58-03fc-43a6-bbc1-e8b67acc5041` 经 `session/load` 重放，按上一轮对话回答暗号 `银杏729`，未读取文件。并行启动 MiMo 与 OpenCode 简短任务，两者分别回复 `MIMO-PARALLEL-729` 和 `OPENCODE-PARALLEL-729`，均 EndTurn；数据库使用同一 SQLite 文件，输出和会话归属未串扰。

## 最终验收（2026-09-30）

- 内置 MiMo 从 PATH 优先启动；PATH 缺失时自动使用官方安装器的 `~/.mimocode/bin/mimo`。`PATH=/usr/bin:/bin ./target/debug/supercode detect` 显示 `MiMo 0.1.15 ✓`；同一 PATH 下真实 ACP 会话回复 `PATH-FALLBACK-OK` 并 EndTurn。自定义 MiMo 命令不受回退影响。
- 临时 macOS 应用使用独立 SQLite `/tmp/sc-p25-real-20260929/desktop.db` 和已配置的真实模型。桌面新会话选择 MiMo、工作目录 `/tmp/sc-p25-real-20260929`，回复 `P25-DESKTOP-REAL-OK`，界面显示“已完成”。另一会话真实模型对 `/tmp/sc-p25-real-20260929-outside` 依次请求目录读取、`approval.txt` 写入和读回；三个 `external_directory` 内联审批均选 Allow once，工具全部完成，最终回复与磁盘内容同为 `P25-DESKTOP-APPROVAL`。
- 关闭并重启临时应用后，历史会话仍显示 MiMo、原 cwd 和最终回复；点击历史会话续聊，经 `session/load` 重放后仅凭上下文回复 `P25-DESKTOP-APPROVAL`。真实 MiMo 与 OpenCode 在同一 SQLite 上并行的 CLI 会话分别回复 `MIMO-PARALLEL-729`、`OPENCODE-PARALLEL-729`，会话状态与归属各自独立。
- 桌面测试发现原有 broker 裁决只发给前端，未写 SQLite approvals；现已补齐。更新后的临时应用再触发真实 MiMo 目录外 read 权限、选择 Allow once，SQLite 联表确认 1 条 `decision=once` 审批归属 MiMo 会话 `3a4d1587-c63a-4651-baf7-c05608613e5a`。先前三次审批在旧版本发生，未追溯补录。
- `just verify` 全绿（core 65 passed / 1 ignored、ACP 合同测试 4 passed、desktop 2 passed；前端构建、fmt、clippy 通过）。首次受限沙箱运行的既有进程组测试因 `pgrep` 权限失败，清理该测试遗留的两个 `sleep` 进程后，在正常 macOS 进程权限下完整复跑通过。

P2-5 验收通过。MiMo 的具体模型由其自身配置决定；本机默认 ACP 曾选中不可用的 image 模型，本次仅在 `/tmp` 测试项目配置可用模型，没有改动全局模型或密钥。
