### 真实本机验收

使用核心 example，沿用本机已有登录，独立临时目录；日志仅留本机 `/tmp/sc-p37-*.log`，未归档原始响应/认证信息。每个示例运行退出码均为 0；真实工具只请求固定 `printf P37-FILE > native-approval.txt`，由 broker 一次性裁决。

| 场景 | 预期与实际 |
|---|---|
| 新线程文本 | 不调用工具，文本拼接 P37-NATIVE，EndTurn |
| 同线程恢复 | thread/resume 同一线程，文本拼接 P37-RESUMED，EndTurn；最终构建再次通过 |
| 工具批准 | 收到真实命令审批 → accept → 工具完成；临时目录文件内容精确 P37-FILE，EndTurn |
| 运行时模式变更并拒绝 | 审批到达后 broker 改为 Plan，明确 decline 已排队请求；P37-DENIED，EndTurn，文件不存在。后续请求按新模式处理由 fixture 验证 |
| 审批等待时取消 | 收到审批后取消；记录 decline，Cancelled，文件不存在；最终构建再次通过 |

复验入口（目录必须为自建的绝对临时目录）：

```sh
cargo run -p supercode-core --example codex_native -- /临时目录 new text
cargo run -p supercode-core --example codex_native -- /临时目录 线程ID text 'Do not use tools or read/write files. Reply exactly P37-RESUMED.'
cargo run -p supercode-core --example codex_native -- /独立临时目录 new approve
cargo run -p supercode-core --example codex_native -- /另一个独立临时目录 new deny
cargo run -p supercode-core --example codex_native -- /另一个独立临时目录 new cancel
```

## 偏差与边界

- 在线协议示例审批枚举与本机稳定 schema 不同；以当前 CLI 的 `untrusted` 为准，固定 read-only + user reviewer，不自动降低沙箱或持久授权。
- 本机原默认模型请求返回 400。验收使用 model/list 公布的默认条目，通过 `SUPERCODE_NATIVE_TEST_MODEL` 单次子进程覆盖，真实推理通过；未修改用户默认模型或认证文件。模型目录不是可用性证明，本任务没有声称原默认模型已修好。实际模型名、endpoint、key、SQLite 均不进入 Git。
- 恢复会重放旧 turn 的 legacy 通知。忽略未消费通知，消费的事件仍严格校验 thread/turn；不忽略未知服务端审批请求。
- 核心库交付边界在动工前写入设计和预写验收；产品选择入口、指挥官 Native 接入和 UI 不在本任务范围。通用 callback 的外部审批队列由宿主管理；推荐 run_with_broker。
- 满事件队列上的取消/错误终态可能无法投递；通过返回结果、取消令牌和进程清理完成收尾，不阻塞等待空位。
