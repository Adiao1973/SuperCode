# P4-1 — v1.0.0 体验基线与问题清单

> 状态：已验收（2026-10-09）。只建立当前产品基线，不实施 P4-2 原型或新 UI；当前发布版本仍为 1.0.0。

## 预写范围与验收

1. 从 dev `8ea10f3` 创建 `docs/p4-1-experience-baseline`，先提交本方案。核对当前源码与 v1.0.0：源码产品部分一致，文档变化不影响产品。已有旧版窗口不作为基线、不改用户数据库/配置。
2. `just verify` 退出 0；`pnpm --filter @supercode/desktop tauri build --bundles app` 构建当前 release App。验收副本使用独立 bundle ID、`SUPERCODE_DB` 临时 SQLite、临时 cwd 与 XDG 配置。数据全为合成；如需规划/审批，使用本机 HTTP/ACP fixture，绝不伪称真实模型验收。
3. 五个页面（会话、指挥官、看板、审批、设置）走查首次配置、输入、计划生成/审阅/确认、审批、终端与重启。记录关键操作步数及路径；截图覆盖 960×640、1280×800、1440×900 内容尺寸，尺寸不足/溢出如实记录。
4. 固定本机型号、系统、显示缩放/刷新率、release 代码版本、数据量和采样方法；记录构建产物 raw/gzip、启动、RSS 与 30s 帧节奏。区分原生 WebKit 与浏览器对照、过程冷启动与系统冷缓存、宿主 RSS 与完整 WebKit 内存；无法准确测量的指标必须注明，不编造数据。
5. 输出可复用的合成数据/采样场景及脱敏证据，明确观察到的缺陷、体验机会、尚未验证假设和关联 P4 任务。若引入仅用于测量的 DevTools/仪器，单独列明开销/与正式包的差异。
6. 退出本轮 App、HTTP/ACP fixture 和 PTY；无测试孤儿进程，无真实凭据/数据库/本机日志入仓。Markdown 链接/围栏、`git diff --check`、文档状态一致；验收通过归档并 --no-ff 合 dev，然后下一项为 P4-2。

## 最终结论与执行结果

P4-1 的出口是建立基线、复现场景与问题清单，已完成；不是宣称 v2.0 性能预算或已发现问题全部修复。没有改产品源码、依赖、接口或版本，因此无需修改 architecture；不提前实现 P4-2。分支从 dev `8ea10f3` 建立，预写提交 `c9ae47c`。产品源码与 v1.0.0 的 diff 为空。

- `just verify` 退出 0：150 passed、1 ignored（需要本机认证的冒烟不计常规通过）；前端构建、fmt、clippy 全过。
- 普通 release App 构建退出 0；另用 `tauri/devtools` 构建测量副本，亦退出 0。保留构建已有 chunk 大小提示，不隐去首包体积。
- 五页三尺寸共 15 张原生截图，另归档 9 张流程证据；所有数据为合成，真实 endpoint/key/SQLite/本机日志不入仓。复现方法见 [附件说明](p4-1/README.md)。
- 本轮普通 App、probe、HTTP/ACP 与终端均退出；用户原有窗口和数据库未修改。

### 设备、采样与量化结果

完整口径与数字见 [baseline.json](p4-1/baseline.json)、[原始帧数组](p4-1/frames.json)。Mac15,9 / M3 Max 16 CPU、40 GPU / 48GiB，macOS 26.5.2 arm64，DPR=2；连接 60Hz 外屏，但没有锁定窗口所在显示器。常用其它应用仍运行，不是独占性能机。

| 指标 | 本轮结果 | 解释与限制 |
|---|---|---|
| 普通 Release 启动 5 次 | 1515 / 715 / 747 / 748 / 724ms；中位 747ms | 退出后启动、OS 缓存温热；含 CUA/AX-ready 往返的上界，不是首帧或磁盘冷启动 |
| 入口静态 JS 图 | raw 1,300,400B；gzip level9 369,794B | 1 文件；全部 319 个 JS raw 11,571,478B / gzip 2,231,808B 不等于首包；不含字体 |
| CSS | raw 52,976B / gzip 9,823B | 当前 dist 的 1 个 CSS |
| 1000 条历史滚动，30s | 1801 样本；p50 17ms、p95 18ms、最大 27ms | 原生 WebKit probe；虚拟列表同时挂载 10～17 条；>50ms 间隔 0 |
| 20Hz 流式输入，30s | 1801 样本；p50 17ms、p95 29ms、最大 33ms | 900 个合成片段完整落库；>50ms 间隔 0；p95 高于规划的 20ms 目标，列为 P4-21 回归关注项 |
| 普通 Release 宿主 RSS | 117,424KiB（单点） | 计划结果页；不含 WebContent/GPU/网络 XPC，不能判断整个 App 内存预算 |
| probe 宿主 RSS | 长历史 126,560KiB；流式后 129,152KiB，各 5 个同值样本 | Inspector 关闭，仍有 devtools feature/探针开销；不能推断泄漏 |

帧间隔是 rAF 调度代理，不是合成器 FPS、GPU 时间或主线程 Long Task 数；WebKit 不支持 longtask observer。测量构建的导航 DCL 153ms/load 170ms 仅供定位，不能替代普通包启动。每种场景本轮只采一次，未来应同设备、多轮复验。输入延迟、20 次切换内存趋势、VoiceOver 与 IME 仍属后续专项，未伪称已测。

### 流程走查与操作成本

下表按有意义的点击、提交或整字段输入计一步，不按字符数或自动化对焦重试计步；没有把合成模型耗时当作真实服务延迟。

| 路径 | 操作与结果 |
|---|---|
| 首次配置 | 空库进入设置 1 步；endpoint/model/高级变量名/假 key 四字段 4 步；保存 key、保存配置、获取列表、验证各 1 步，共 9 步。显示“已保存到本机”和“两任务/两批次验证通过”；无环境 key，走 SQLite 凭据。这里是 loopback fixture，不是真实模型验证 |
| 新会话 | 已有项目内新建→输入 fast→运行，3 步；cwd 预填，返回合成文本 |
| 指挥官 | 进入→目标/目录/Agent 三字段→生成→展开两项 prompt→审阅执行→确认，共 9 步；确认前 sessions 数保持初始 12，确认后才派单 |
| 审批 | 执行中进入审批中心→拒绝一次→返回指挥官，3 步；卡片消失且决策持久化。fixture 拒绝工具后正常 end_turn，因此最终成功不等于工具获得允许 |
| 结果与重启 | 两任务结果可读；退出→启动→指挥官→选择历史，4 步；计划和两会话结果保留，5 次启动前后会话数相同，没有重新派单 |
| 终端 | 打开→输入命令→Return→关闭，4 步；中文与 ANSI 正常；小/大窗口 stty 分别 16×66 / 16×135，关闭后 shell 退出 |
| 看板/设置 | 12 张卡片四列可读；设置加载期间 Agent 为 0，完成探测后 5 项。没有把短暂加载态解释成未安装；本轮未重新覆盖全部拖拽、真实认证场景 |

### 确认的问题、体验机会与假设

| 性质/优先级 | 证据和影响 | 后续归属 |
|---|---|---|
| 确认缺陷 / 高 | 计划确认弹层打开后焦点留在 HTML，Tab 可进入背景摘要，Esc 未关闭；手写弹层缺少焦点约束 | P4-14、P4-22 |
| 确认体验缺口 / 高 | 结果显示正文和本地 UUID，没有直接跳到对应会话的入口 | P4-15 |
| 体验机会 / 高 | 会话主导航+会话侧栏共 448 CSS px，960 宽时占 46.7%；顶部输入/权限区进一步挤压阅读区 | P4-6、P4-9 |
| 确认体验缺口 / 中 | 历史及结果 Markdown 以原始标记展示，代码/表格阅读成本高 | P4-10 |
| 体验机会 / 中 | Agent 选择是逗号字符串，目录手填；缺少项目选择引导 | P4-13、P4-18 |
| 体验机会 / 中 | 设置为长页，小窗口需滚动才能完成配置；Agent 探测时短暂显示 0 缺少明确骨架反馈 | P4-18、P4-19 |
| 已测性能关注 / 高 | 20Hz 的 p95 29ms；连续文本更新成本可能有关，尚无 CPU profile，不能断言根因 | P4-11、P4-21 |
| 待验证假设 | 加入动效可能与虚拟滚动/拖拽 transform 竞争；IME、VoiceOver、减少动态需要专项验证 | P4-2、P4-17、P4-22 |

### 偏差、归档与下一项

本轮要测发行性能，因此以构建后的原生 Release App 替代通用流程中的 `pnpm tauri dev` UI 核对；普通截图/启动与插桩帧采样分别记录，没有用浏览器替身验收。初次 HTTP fixture 漏掉 finish_reason 导致契约错误，修复 fixture 后重试通过，不归为产品缺陷；初次标题栏计入尺寸的截图已排除，用校正后的内容尺寸重新采集。

发现的问题是 P4-1 必须交付的基线清单，不是本任务承诺修复的功能。后续任务必须解决自己的出口，尤其 P4-21 不得把本轮 29ms 记为预算通过。下一任务为 P4-2 视觉/交互原型与库选型，状态待办；无 main/tag/Release 变更。
