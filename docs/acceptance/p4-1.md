> 状态：进行中（2026-10-09）。只建立当前产品基线，不实施 P4-2 原型或新 UI；当前发布版本仍为 1.0.0。

## 预写范围与验收

1. 从 dev `8ea10f3` 创建 `docs/p4-1-experience-baseline`，先提交本方案。核对当前源码与 v1.0.0：源码产品部分一致，文档变化不影响产品。已有旧版窗口不作为基线、不改用户数据库/配置。
2. `just verify` 退出 0；`pnpm --filter @supercode/desktop tauri build --bundles app` 构建当前 release App。验收副本使用独立 bundle ID、`SUPERCODE_DB` 临时 SQLite、临时 cwd 与 XDG 配置。数据全为合成；如需规划/审批，使用本机 HTTP/ACP fixture，绝不伪称真实模型验收。
3. 五个页面（会话、指挥官、看板、审批、设置）走查首次配置、输入、计划生成/审阅/确认、审批、终端与重启。记录关键操作步数及路径；截图覆盖 960×640、1280×800、1440×900 内容尺寸，尺寸不足/溢出如实记录。
4. 固定本机型号、系统、显示缩放/刷新率、release 代码版本、数据量和采样方法；记录构建产物 raw/gzip、启动、RSS 与 30s 帧节奏。区分原生 WebKit 与浏览器对照、过程冷启动与系统冷缓存、宿主 RSS 与完整 WebKit 内存；无法准确测量的指标必须注明，不编造数据。
5. 输出可复用的合成数据/采样场景及脱敏证据，明确观察到的缺陷、体验机会、尚未验证假设和关联 P4 任务。若引入仅用于测量的 DevTools/仪器，单独列明开销/与正式包的差异。
6. 退出本轮 App、HTTP/ACP fixture 和 PTY；无测试孤儿进程，无真实凭据/数据库/本机日志入仓。Markdown 链接/围栏、`git diff --check`、文档状态一致；验收通过归档并 --no-ff 合 dev，然后下一项为 P4-2。
