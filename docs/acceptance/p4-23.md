## 预写验收

1. `cargo test -p supercode-core upgrade_v1`：从 1.0 的迁移 1～7 建库，保留空间、会话、消息、工具、审批、规则、任务、模型配置、合成凭据和计划；应用全部新迁移后逐表核对，偏好默认值正确，重开幂等。历史 draft/running/succeeded 计划不能因数据库升级产生会话或修改执行状态。此项只证明持久层，App 启动恢复单独验收。
2. `just verify`：类型、前端测试、构建预算、fmt/clippy/Rust 全绿。
3. 独立本机数据库的实际 Tauri App：内部只读复制用户已授权的 MiMo 配置与密钥，不输出内容；模型就绪→真实生成三个无工具标记任务→审阅 Agent、提示词和依赖→显式确认→OpenCode/Codex 两根任务并行→依赖任务→结果与会话跳转→退出重启，确认结果保留且没有再次派单。确认之前不能创建执行会话。
4. 独立 ACP fixture：并发审批允许/拒绝、等待审批取消、退出再开、依赖阻断；明确不冒充真实模型验收。
5. 独立临时 Git 项目：worktree 创建、执行目录、看板空间变更不影响会话所有权；PTY 的 pwd、中文/ANSI、分栏、Ctrl-C、关闭重开及 App 退出清理。
6. 归档仅合成截图与去敏状态/计数；真实 endpoint/model/key、SQLite 及附属文件不得进入仓库。清理隔离库中复制的凭据；用户原库不修改。

### 验收中发现与修复

最终检查暴露已有看板测试竞态：`findByRole(dialog)` 仅等待弹层存在，详情 IPC 可能尚未返回。测试改为显式延迟上下文响应，先核对加载态，再返回数据并等待标题，避免以渲染调度碰巧完成为通过条件。原生行为无需修改。

### 历史连接失败与区域复验

沿用原 key；对照站点 TLS 正常，配置的 MiMo 集群经系统路由、已有 HTTP/SOCKS 代理、TLS 1.2/默认 TLS 均在握手断开。两个独立 DNS 查询获得的两个真实地址也失败；没有关闭证书校验或改系统网络配置。见 [连接诊断](p4-23/connection-diagnostics.json)。

依据 [MiMo 官方接入文档](https://mimo.mi.com/docs/zh-CN/tokenplan/Token%20Plan/quick-access)，另一区域入口的无认证 HTTPS 连通。最初自动审批因缺少新地址授权而拒绝认证请求，当时请求未执行。2026-10-18 用户明确授权“允许使用官方新加坡集群，继续验收”，授权边界已满足。随后沿用现有 key，Bearer 目录请求、官方 api-key 目录/最小推理请求、两种请求头并用的推理请求均返回 HTTP 401；服务端 JSON 错误归类为 invalid_key，未归档正文。不能据此确认 key 在原区域失效或已到期。

在独立 SQLite 中配置授权区域并按该 origin 建立凭据作用域，原生 App 选择 OpenCode/Codex，输入三任务标记目标并点击生成，返回“指挥官 LLM: HTTP 状态 401”。0 计划、0 执行会话，无法继续审阅和执行。关闭 App 后清理隔离库所有复制的配置/凭据并 checkpoint/VACUUM，两表均 0。原用户配置与 key 未修改。此次没有生产代码变更，沿用上一轮全绿检查；不以 fixture 替代真实出口。

### 中国入口恢复后的最终闭环

用户要求再次尝试中国入口且不要使用 VPN。直接 HTTPS 与最小推理成功（HTTP 200），未设置 HTTP 代理、探针显式禁用 HTTP 代理；DNS 仍返回虚拟地址，所以不据此宣称底层 TUN/VPN 路由已被验证关闭。没有修改系统网络设置或关闭 TLS 校验。

真实执行预检发现 Codex ACP 的 npm 缓存 `ENOTEMPTY`。确认无进程使用后仅改名保留对应缓存备份，npx 从官方包重建并通过真实版本检查，没有修改登录凭据。重试同一草稿后两根任务并发，Codex 成功；OpenCode 默认免费服务出现限流，使用 App 取消，保留该计划及两条会话，依赖任务未派单。

为验证 OpenCode CLI 在可用后端下的完整链路，使用 [验收专用启动器](p4-23/real-opencode-launcher.py)：执行的仍是真实 OpenCode 1.18.30，版本探测直接转交真实 CLI；只为该子进程设置隔离配置/数据目录和内存中的兼容接口配置，沿用用户授权的 MiMo 原服务、原 key。未修改全局 OpenCode 配置，未用 fixture 回答。默认免费服务的额度/限流未宣称修复。

在 App 再次调用真实 MiMo 生成新草稿，审阅三项完整提示词及两批依赖，确认执行。最终 a/b/c 全部 succeeded、精确匹配预期标记，根会话实际重叠，子会话晚于两根完成；结果/会话跳转及重启对照通过。失败的前一计划保留 cancelled，不篡改历史状态或重跑已取消计划。最终 5 条持久会话=前一轮 2 条+成功轮 3 条；UI 另有未持久化“新会话”草稿。

关闭 App 后，复制的配置和凭据清零、checkpoint/VACUUM，并移除验收专用 OpenCode 数据/日志目录。原用户 SQLite 全程只读。最终检查全绿，接口/协议/数据模型没有变更，无需改 architecture。
